# `identity_file` 是什么

`"identity_file": "data/identity.json"` 是网关的**客户端身份持久化存储**——记录“每个下游 key 对应的 Claude Code 客户端身份(device_id)”。

## 为什么需要它

上游(第三方)判断“一个 key 是否多人共用”的信号之一就是 `metadata.user_id` 里的 **device_id**:真实 Claude Code 安装在一台机器上,它的 device_id 是装机时生成、之后**永远不变**的(你抓包里那串 `0afd5711...5cb` 就是)。

所以网关必须保证:**同一个下游 key 的所有请求,永远呈现同一个 device_id**。这就是身份按 key 隔离的核心：

- 某个 key **第一次**经过网关时,随机生成一个 64 位十六进制 device_id,写入这个文件
- 之后该 key 的所有请求(包括网关**重启后**)都从文件读回同一个值,永不更换
- 不同 key 生成不同 device_id → 在上游眼里是互不相干的多个独立用户

如果不落盘,网关每次重启 device_id 都会变,上游视角则是“该 key 频繁更换设备”,属于异常特征。

## 文件内容长什么样

```json
{
  "e3b0c44298fc1c14afae4c41f2b09e29": { "client_id": "a1b2...(64位hex)" },
  "另一个key的sha256哈希前16字节":       { "client_id": "f4e5...(64位hex)" }
}
```

注意两点：
- key 本身**不落盘**,只存它的 SHA256 哈希(避免泄漏)
- 这个文件**不要随便删**——删了等于所有用户“集体换了新电脑”;只在你想主动重置某个 key 的身份时才有意义

它移植自 sub2api 的 `identity_service.go`(sub2api 用 Redis 按账号 ID 存指纹,这里是等价的本地 JSON 文件实现,以后要换 Redis 也不影响调用方)。你现在浏览器开着 `http://127.0.0.1:8080/` 说明网关在跑,但文件还没生成——**它会在第一个携带 key 的 `/v1/messages` 请求到达时自动创建**。可以等阶段 2 联调时再验证。`data/` 目录我建项目时已经预置好了。
